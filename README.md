# AI痛点雷达 · ai-pain-point-research

**从中国普通人的真实求助里，寻找值得做成AI教程的选题。**

这是一份 Agent Skill：让支持 Skills 的 AI 助手从社区正文、评论和追问中寻找学习与使用卡点，再转成完整大教程或单个小卡点。它不是自动抓取所有平台的爬虫，也不是凭工具功能拼出来的热点清单。

作者：[川云添 · cytxnyu](https://github.com/cytxnyu)

## 安装

```bash
npx -y skills add cytxnyu/ai-pain-point-research -g --all
```

也可以下载仓库，将 `skills/ai-pain-point-research` 整个目录放入客户端支持的 Skills 目录。具体位置以该客户端说明为准。

## 直接使用

```text
使用 $ai-pain-point-research，调研最近30天中国普通人从零学习AI和实际操作的真实痛点，给我20个大教程和20个小卡点选题。
每题给具体停住步骤、原始来源、日期、实际数字及口径、教学交付结果和待验证点。
搜索次数、搜索指数、作品互动、独立求助分开；证据不足的标待补证，不偏成程序员技术问题。
```

也可以缩小任务，例如：只研究手机AI使用、第一次做PPT，或只找5个能独立成篇的小卡点。数量、时间窗和研究范围服从你的请求。

## 明确覆盖的10个平台

| 分工 | 平台／社区 |
|---|---|
| 优先寻找普通人的学习和操作问题 | 抖音、小红书、哔哩哔哩、知乎、酷安、即刻 |
| 补充具体上手与使用案例 | Linux DO、吾爱破解、V2EX |
| 核对与上述卡点相关的故障 | GitHub Issues / Discussions |

列入名单不代表每次都能访问。研究时逐项记录实际覆盖、读取范围和缺口，不把搜索卡片冒充完整评论。技术社区的高赞讨论不自动代表中国大众需求。

## 核心方法

1. 从“什么人、想做什么、卡在哪一步、出现什么现象、想得到什么结果”出发。
2. 优先读真实求助和跟做失败，再用官方文档核验解决路径。
3. 排除营销、求资料、同名词、重复搬运和不适配目标人群的技术讨论。
4. 分开判断问题存在、独立重复、搜索信号、解决方案是否实测。
5. 大教程走到可用成果；小卡点打通一个障碍，并给验收标准。

低点赞的具体问题可能有价值；高互动的课程内容不一定能证明卡点。没有实际搜索次数时，不编造“全网搜索最多”。普通人用AI做第一个网页、被必要的API配置卡住可以研究；纯开发、运维、模型训练和性能调优不进入默认大众选题池。

## 交付什么

- `report.md`：痛点与选题、来源、日期、数据口径、教学路径、产物及验收。
- `research.json`：结构化证据和选题台账。
- `search-log.md`：真实查询、筛选、去重、排除项与访问缺口。

只需要聊天结果时可直接要求简版，不强制生成文件。

## 环境与验证

- 支持 Agent Skills 的客户端。
- 实际调研需要客户端可用的网络搜索或浏览器工具；部分平台内容需要登录或可能访问受限。
- Python 3.10+ 可运行证据校验器，仅使用标准库，无额外Python依赖。
- 使用上方 `npx` 安装命令需要 Node.js/npm 和网络。

从仓库根目录运行：

```bash
python skills/ai-pain-point-research/scripts/validate_research.py path/to/research.json
```

校验器检查结构、引用、数据缺失、指标口径和已记录状态。通过不等于来源真实性、热度或教学方法已得到验证；原页面和实际操作仍需分别核对。
