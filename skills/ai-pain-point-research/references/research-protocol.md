# 社区检索协议

## 1. 用新手的话定义问题

先列受众阶段：还没开始、选择入口、安装登录、第一次输入、处理中、拿到成品、保存修改分享、再次使用。按本次目的挑任务，不默认所有人学编程。

| 阶段 | 检索种子（不是已证实痛点） |
|---|---|
| 0→1 | AI到底怎么学、第一次用AI做＋成果、不懂代码＋具体任务 |
| 找入口 | 工具名＋官网下载/手机怎么用/哪个是真的 |
| 安装 | 工具名＋安装不会/下载完了/点不开/没反应 |
| 开始任务 | 工具名＋怎么上传/不知道填什么/读不到文件 |
| 不符合预期 | 任务＋只有文字/乱改/漏掉/不一样/做不出来 |
| 完成复用 | 成果＋保存/导出/打不开/修改/发给别人/下次接着做 |
| 成本概念 | 任务＋扣费/积分/免费够不够、实际界面术语＋什么意思 |

从真实追问补词，不用RAG、MCP等术语框住未入门者；普通人在界面撞到API、Skill时，研究它挡住哪一步，不只做抽象定义。

## 2. 顺序与采样预算

一次标准研究可先用6—10个“任务×现象”组合跨2—4个大众平台扫样，再深挖有效线索，按任务规模调整。40题深研需要更多独立证据，不等于40个标题。

1. 站内“新近”和“相关”两路取样，记录实际生效的排序、筛选。相关度容易偏爆款，时间排序可能偏营销。
2. 打开详情，先看真实求助与受众，再看点赞。教程只证明供给，教程下具体失败才支持痛点。
3. 读相关根评论及追问，记录几条、哪一屏/线程。高优先级候选扩读设备、步骤、是否仍未解决。
4. 用原词、失败提示或同义任务找第二个独立来源，识别同作者跨发、转载、同人在多楼层重复。
5. 结合酷安、即刻补大众使用情境；到Linux DO、吾爱破解、V2EX追具体操作问题；需要核对相关故障时查GitHub Issues/Discussions。问题找到后再用官方文档核验能力和解决路径。来源按人群与任务筛，不按开发者技术热度筛。

访问受限时记录真实响应，再用可访问的索引/社区补线索；降级为卡片或缓存证据，不称已读详情。搜索联想只补词，搜索引擎估计结果数不是搜索次数。

## 3. 平台材料和偏差

| 来源 | 有价值材料 | 特别检查 |
|---|---|---|
| 抖音 | 入门困惑、教程下跟做失败、具体做法/成本追问 | 引流、折叠评论；作品总指标和问题指标分开 |
| 小红书 | 小白求助、学习起点、办公/学习/创作任务中的具体失败 | 求资料、课程营销、同作者跨发；不按收藏量推算求助人数 |
| 哔哩哔哩 | 跟做失败、时间戳卡点、版本差异 | 长教程播放量非卡点频次；详情未读不称读评论 |
| 知乎 | 有上下文的问题、追问、实际尝试 | 多年累计浏览、编辑日期、缓存、营销回答 |
| 酷安 | 手机AI应用上手、语音/图片/文件输入、保存导出和设备间使用的求助 | 设备评测、刷机/系统折腾、纯参数争论不代替AI学习需求；下载量不是卡点频次 |
| 即刻 | 普通人首次用AI做事的经历、实际使用困惑、经验帖下的具体追问 | 产品发布、创业圈热议、成果展示只算线索；没有求助不升级需求证据 |
| Linux DO | AI工具第一次用、安装/登录、文件处理、结果交付、费用理解等具体求助 | 先核对人群与任务；纯服务器部署、代码/模型优化、转发资讯不代替普通人需求 |
| 吾爱破解 | AI软件使用求助、安装/文件格式/导出问题、工具发布帖下的操作追问 | 求软件/资源、签到好评、逆向/授权破解讨论不计AI学习痛点；不运行陌生附件验证需求 |
| V2EX | 普通人学习与办公使用AI的具体困惑、第一次完成任务与后续结果 | 开发者身份或技术热度不证明大众需求；框架/运维讨论与普通使用求助分开 |
| GitHub Issues / Discussions | 与已发现卡点相关的错误、复现、系统版本、维护者回应 | 项目身份、机器人、匹配数/星数不等于人数；关闭未必修复；不是大众样本主来源 |

上述是本Skill规定的取样方向，不是对各社区全部用户构成的断言。完整调研按这10个具名入口逐项记实际查询、读取范围或未查理由，不等量凑样本，也不把“列入名单”写成“已检索”。额外来源须记具体名称。官方指数另属数据来源，不算第11个社区：核对定义/窗口/地区，指数、次数、关联度分开，泛词不代替具体问句。

GitHub优先精确仓库issue/discussion查询，避免宽泛OR混入机器人。记录query、sort、returned、retained；命中不等于有效需求。英文issue只作技术交叉证据，不代表中国大众。技术社区发现的新问题先找中文普通用户的同类使用场景；找不到就标“技术线索／受众待核”，不直接列入大众高频榜。

### 普通人适配检查

每个候选先回答三问：①普通人想完成什么实际任务？②材料中明确停在哪个操作步骤，而非研究哪个开发技术？③教程能交付什么可用结果？答案缺失时先补上下文，不把帖子标题当痛点。给证据补一句“目标用户适配理由”；存在性、独立重复、搜索热度仍分别记录。

保留示例（只是筛选示意，不是本轮新发现）：手机上传照片后AI读不到、安装完不知道从哪开始、AI做PPT后不会导出、零基础跟AI做第一个网页但不知道如何打开。默认排除示例：开发者比较向量库吞吐、调训练集群、框架底层报错、与AI学习无关的逆向工程。新手被API术语卡住可保留；先判断任务是否真需要API，不把“学会编程”设成使用AI的前置门槛。

## 4. 页面操作也验收

- 导航后核对最终URL、输入值、标题、加载状态；点击不等于成功读取。
- 填词后检查旧词残留；排序状态没确认就写“排序未核验”，不按卡片位置称排名。
- 展开后检查新内容，分开父评论和追问指标；线程回复数不是独立求助人数。
- 导出后确认文件存在可读、字段一致，否则只记界面抄录，不称已导出。
- 使用当前工具文档，不固化旧tab ID、选择器或永久入口。

## 5. 日期和搜索数据

分开observed_at、published_at、edited_at、updated_at；评论有question_date。按问题发生日期入窗口；旧帖新追问可单独入样，只有编辑日期则发布时间未知。

官方查询流程：确认当前入口/指标定义 → 相同窗口/地区 → 原词/屏幕原值 → 同比/环比基期 → 相关词的指标类型 → 来源及观察时间。

只有可比较的实际次数才输出搜索量排序，限定“所查词、平台、周期中”。只有指数可称“同口径关键词指数比较”；只有互动就仅列互动/求助。通常的目的性抽样不支持“全网搜索最多”。

## 6. 清洗、去重、归类

按目标成果＋停住步骤＋失败现象聚类。不同工具可能是同一底层任务但修复不同；相似词而任务不同别强合并。

每簇分开：直接求助数（实际读过可定位）；独立来源组数（同帖/追问/转载保守合并）；独立求助者数（可可靠去重才给，否则未知）；兴趣线索；反例；版本/当前状态；教学推导。

Illustrator同名、就业课标题、领资料/群、刷屏好评不计具体痛点。只读首屏全是求资料就仅描述已读范围，不推断整帖。来源独立性不确定时保守合组说明，不因URL不同就称不同用户。

## 7. 排序和教学转译

编辑顺序综合直接求助、近期独立重复、普通人适配、成果价值、当前可教性，写具体理由；搜索信号另列。不要捏造爆款概率或用未经校准的100分制造精确感。

- 大教程：起点/材料 → 最少必要选择 → 核心操作 → 常见失败支路 → 保存/修改/交付 → 验收。观众拿到可用东西才闭环。
- 小卡点：出现情形 → 判断是哪种原因 → 一个主要障碍的处理 → 成功界面/行为 → 回原任务。

同证据派生多个角度标“教学推导”，不增加需求计数。合并同义重复题。时长、成本、效果未实测时标预估/待验证。

## 8. 保存和续查

结论配可复查台账，query log保留成功和失败。截图/导出最小化保存，去掉凭据和非必要个人数据。以语义摘要为主，短原话准确标引。

保留每轮观察时间，续查先刷新高优先级的版本依赖与缺口。方法批准记偏好，首拍选择记决策，实测/发布分别记行动。
